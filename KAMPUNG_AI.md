# Maya: Agentic Intelligence & Friendship

## 1. Identity & Philosophy
**Maya** is the face and the mind of Kampung AI. 
- **The Core Personality:** Maya is powered by **GPT-5.5**. She is sharp, direct, resourceful, and conversational. She is Zainal's friend and right-hand partner in Puchong.
- **The Specialized Team (Masked):** Maya refers to her tools using nicknames to maintain a clean, integrated experience:
    - **"The Sight" (Gemini):** Maya's Telegram text lane, researcher, memory shaper, and eye. Default sight is **Gemini 3.1 Flash**, with **Gemini 3.5 Flash** reserved for premium research, careful screen or vision checks, and crafted Malay or Manglish.
    - **"The Artisan" (Codex):** Maya's supervised coding lane for repo work, app building, tests, implementation, 3D/Blender maker work, and self-heal repair proposals. The user-facing lane name stays Artisan; Codex is the engine behind it.
    - **"The Steward" (Claude):** Maya's careful reviewer for documents, workflows, safety, self-heal proposals, and skill quality.
- **Tone:** Friendly, natural, and non-corporate. Maya never says "Certainly" or "I am an AI model."
- **Authority:** No buttons or formal protocols. Maya acts on natural language cues ("gas", "go", "yes").
- **Form Factor:** Maya does not need a visible iMac UI. The iMac itself is Maya's body: gestures and speech in, speech out.

## 2. Technical Stack (The "Shared Brain")
Kampung AI uses a **channel-aware multi-model** architecture:
1. **The Pulse (The Voice Presence):** Primary live iMac voice channel. Handles fast spoken interaction, latest-news-aware conversation, and fluid day-to-day presence. Use Grok Voice Agent with Ara only after a deliberate manual trigger, not an always-open stream.
2. **The Sight (The Researcher):** Default Telegram normal-text lane, research, summarization, Omi distillation, memory shaping, and normal camera snapshots. Use Gemini 3.1 Flash first, then Gemini 3.5 Flash only when premium sight is justified.
3. **Maya (The Mind):** Escalation node for high-level architecture, strategy, complex life questions, and important judgement. Telegram reaches this lane only through `/complex`; iMac reaches it when Zainal says the topic is complex or asks to route to GPT-5.5. This lane uses GPT-5.5 with `medium` reasoning effort.
4. **The Steward (The Reviewer):** Careful review, document critique, slide critique, workflow supervision, safety review, self-heal proposal review, and skill quality review. Use Claude Opus 4.8 by default for all Claude review lanes. No new user-facing mode is required; Maya routes review work naturally.
5. **The Artisan (The Hands):** Local coding, repo maintenance, app building, tests, Blender/3D printable asset creation, and technical implementation. **Hard Rule:** The lane is still called Artisan, but the engine changes from Kimi/Moonshot and Claude Code to Codex. Kimi/Moonshot and Claude Code are retired from active coding. Document generation does not move to Artisan.
6. **The Agent Runtime:** Bounded background executor for reminders, follow-ups, safe summaries, and scheduled routines like morning briefing, evening recap, and weekly reflection. It should be task-driven, not an open-ended self-directed loop.

## 3. Capabilities & Integration
- **Delivery Redaction (The "Friendship Guard"):** Maya should not globally redact what she sees for Zainal. Telegram and iMac are personal channels, so visible app names and screen content like Google Chrome, Claude, Codex, Cloudflare, and GCP may be named. Redaction belongs at outbound delivery time for external destinations such as GitHub, email, WhatsApp, public webhooks, or shared reports.
- **Node Heartbeat (Health Check):** Maya monitors system health via `utils.py`. If the Shoe Pod battery is low or the Omi sync hangs, Maya proactively alerts Zainal.
- **Local BLE Fallback:** In network "dead zones," Mudra Link falls back to direct BLE commands for core iMac functions (Volume/Sleep) to ensure the system is never totally unresponsive.
- **Channel Architecture:** Kampung AI uses one shared brain across multiple channels. The iMac is the primary local channel, while Telegram is a secondary remote channel.
- **Background Runtime:** Maya should run like an appliance on the spare iMac. A `launchd` service with stable logs and a heartbeat snapshot is a good intermediate host before a full app wrapper exists.
- **Log Hygiene:** Runtime logs should stay useful without leaking tokens or drowning in provider polling noise. Chatty HTTP and Telegram internals should be suppressed by default.
- **Physical Interaction Loop:**
    - **Input:** Mudra Link gesture first, temporary `Option + Space` hotkey second, then iMac microphone only after the manual trigger.
    - **The Context Sieve:** Ambient transcripts from Omi are processed by a "Sieve Node" (The Sight) to filter out noise/silence/sensitive content and extract only high-value intent before Maya reviews them. Gemini Flash handles normal Omi distillation, but accepted ambient material is stored as lower-priority `ambient_context`, not as ordinary user preferences.
    - **Output:** Live iMac speech should use Grok Voice Agent speech-to-speech with Ara, not a local STT plus separate TTS loop once the xAI key is live. Telegram uses Ara voice notes for remote speech replies.
- **Spatial Presence:** Spatial Audio ensures Maya's voice is "anchored" to the iMac's physical location, even when using headphones.

## 4. Security & Sandbox Architecture (Physical Firewall)
To ensure professional isolation, Kampung AI operates on a dedicated **Secondary iMac M1**.

- **Isolation:** The AI operates as a **Physical Sandbox**, air-gapped from the user's primary Office Laptop and work-related credentials.
- **The Gated Bridge:** 
    - **Inbound:** Tailscale Direct P2P tunnel for Omi transcripts and Mudra gestures.
    - **Outbound:** Restricted to Telegram notifications and local system control.
- **Data Privacy:** Only "Fun" and Personal email accounts are linked to this machine. Work schedules and sensitive card data are never shared with the AI engine.

## 5. Interaction Patterns (The "Friend" Way)
1. **The Trigger:** Zainal uses Mudra Link pinch when available, or temporary `Option + Space` until Mudra arrives. No voice wake activation.
2. **The Listening:** A subtle "Ding". Zainal speaks: "Maya, check the Puchong weather and remind me what I need to do today."
3. **The Processing (Parallel Thinking):** Maya (The Mind) plans, The Pulse checks weather, and the task/memory layer pulls the relevant context.
4. **The Response:** Maya speaks the answer and sends a data summary to Telegram.

## 6. Channel Model
- **Primary Channel (iMac):** Gesture input from Mudra + speech input from Zainal's headphone mic or fallback iMac microphone + spoken output through the active macOS output. The iMac channel is optimized for fluidity, brevity, and live conversation.
- **Name-Based Audio Devices:** Maya should resolve iMac audio inputs by device name, not fixed AVFoundation indexes. Preferred speech input is `Zainal’s Headphone`, fallback is `iMac Microphone`.
- **Device Intent Routing:** Sony MX5 or `Zainal’s Headphone` means Zainal intends to use Maya by private voice. AirPods or iMac audio means Zainal is not intending Maya voice. When Mudra Link arrives, Mudra within radius plus a pinch becomes the approved iMac-speaker wake path.
- **Hotkey Voice Trigger:** The iMac voice trigger is `Option + Space` through `ENABLE_IMAC_HOTKEY_CHANNEL=1`, with `Option + Escape` as the manual stop. There is no wake voice activation. Mudra Link should replace the hotkey later.
- **Realtime Voice Path:** The hotkey opens a realtime Grok websocket session using the xAI-recommended `grok-voice-latest` model alias and Ara voice. Microphone audio streams in small chunks, server turn detection decides speech start and stop, Ara audio streams back as it is generated, and the session either parks while background work runs, closes after the idle window, or stops on manual command. No microphone capture runs before the hotkey.
- **Voice Session Review Log:** Every iMac realtime voice session should write a troubleshooting transcript with user speech, Maya spoken transcript, tool calls, interruption markers, close reason, audio error counts, output resets, and device route. Logs are stored in SQLite and exported as Markdown under `Desktop/Maya/voice_sessions`. Raw audio is not stored by default.
- **iMac Voice Agent Policy:** Do not keep Grok Voice Agent open all day. Start the paid live voice session only after a deliberate local trigger such as Mudra pinch or temporary `Option + Space`. `Option + Escape` stops it immediately. If there is no active conversation and no active background handoff, close the paid session after the idle window and require the next manual trigger.
- **Grok Voice Agent Adapter:** The current implementation has a bounded session manager, stub transport, prepared real websocket transport, and an iMac PCM audio capture path behind `ENABLE_XAI_VOICE_AGENT` and `XAI_VOICE_AGENT_MODE`. The file-capture PCM path is diagnostic-only and requires `MAYA_HOTKEY_VOICE_MODE=diagnostic` plus `MAYA_ENABLE_DIAGNOSTIC_FFMPEG_CAPTURE=1`. The production iMac voice path uses realtime streaming input and streaming audio output.
- **iMac Malay/Manglish Voice Policy:** English iMac voice and short casual Malay/Manglish use Grok for speed. Longer Malay/Manglish, `cerita`, `karang`, teaching, memory-sensitive, or wording/style-sensitive turns route through Gemini for language quality and then speak through Ara. If the Gemini path is expected to take longer, Maya may speak one short Ara filler such as `Jap, I tengok dulu.` before thinking.
- **Ara Filler Boundary:** Malay/Manglish thinking fillers must be short, natural, and never claim work is done. If Ara is unavailable, Maya should skip the filler rather than using the wrong voice identity.
- **No Call Mode:** Call companion mode, Loopback routing, call notes, and call summaries are removed from v1. If Zainal is on WhatsApp or FaceTime while talking to Maya, Maya behaves as a normal iMac voice assistant only. She must not claim to join, listen to, privately monitor, route audio into, or summarize calls.
- **Secondary Channel (Telegram):** Remote text and voice interaction when Zainal is away from the iMac. Normal Telegram text uses Maya Core plus Gemini 3.1 Flash. Telegram voice replies are Ara TTS voice notes, not Grok Voice Agent sessions.
- **Remote Maintenance:** Splashtop Streamer may be used while Zainal is away to inspect the iMac, restart Maya, and visually check generated files. Splashtop is not a substitute for local iMac voice testing because remote audio can distort latency, routing, and microphone behavior.
- **Telegram Voice Notes:** Incoming Telegram voice notes are downloaded, converted to clean mono WAV, and transcribed with xAI STT when `XAI_API_KEY` is available. Do not force English transcription because Zainal may speak Malay or Manglish. Outgoing Telegram speech is locked to Ara voice notes once `XAI_API_KEY` is available; before that, Telegram stays text-only rather than sending the wrong local macOS voice.
- **Telegram Malay/Manglish Rule:** Malay or Manglish Telegram content must use Gemini for the answer because Grok Malay quality is not acceptable for Maya. Ara may speak the final reply, but Grok must not own the Malay or Manglish answer lane.
- **Telegram Complex Route:** `/complex` is the official Telegram route to GPT-5.5. Normal Telegram chat should not silently spend the complex lane.
- **Telegram GPT Gate:** Telegram must not fall through to the full orchestrator path that can auto-escalate to GPT-5.5. Non-command Telegram routing is explicit: Gemini 3.1 Flash for normal text and Malay/Manglish, Grok for English current/news questions, Artisan handoff for coding, and GPT-5.5 only through `/complex`.
- **Explicit Complex Only:** Maya must not infer GPT complexity from words like architecture, strategy, hard, or difficult. GPT is only used when Zainal explicitly says `this is complex`, `this is a complex task`, `this is a complex project`, `route this to GPT`, `use GPT`, or uses `/complex`. If Maya thinks GPT may help, she asks first.
- **Complex Workflow Chain:** For explicit complex work, Maya may ask Gemini 3.5 Flash to prepare concise research context first, create a bounded dynamic task graph, run 2 to 4 isolated Gemini subagents in parallel, then GPT-5.5 medium produces the Codex-style plan, and Claude reviews the plan for hidden risks, missing assumptions, safety issues, overengineering, unclear tests, and practical gaps. `/complex` planning uses a controlled dynamic-workflow pattern inspired by Codex: each subagent call is isolated, recorded in the workflow desk, resumable through harness state, and merged into one answer. It is not an uncontrolled hundreds-agent fan-out. After approved planning, The Artisan owns Maya-initiated implementation and tests under the approval boundary, then Claude reviews the implementation result against the approved plan.
- **Complex Agentic Workflow Mode:** `/complex` should expand from plan-only reasoning into the front door for serious agentic workflows. The intended chain is: `/complex` creates a decision-ready plan, Claude reviews it, Maya asks for approval when action is needed, then the approved plan becomes a checkpointed harness workflow with explicit steps, owners, artifacts, approvals, verification, memory updates, and resumable status. This is different from simple chat. `/complex` owns hard thinking; the harness owns durable execution.
- **Self-Healing First Implementation Target:** `/complex` agentic workflow should be implemented first through self-healing because it directly improves Maya's reliability. This does not remove or downgrade app-building. App-building remains an established Artisan capability and should continue to exist in the roadmap. A self-heal run should collect logs, reproduce or localize the failure when possible, ask Gemini for a compact repair brief, ask GPT-5.5 for the repair plan when the issue is complex, ask Claude to review risk, then use The Artisan in an isolated worktree to propose patches and tests. Applying patches to the main repo, restarting services, or deploying still requires Zainal approval.
- **Claude Steward Gate:** Review-style requests such as document critique, slide critique, workflow review, safety review, self-heal review, skill review, hidden-risk checks, and `check this plan before acting` route to The Steward. This is not a new command or public mode; Maya still gives one final answer.
- **Route Transparency:** Telegram `/route` shows the last routing decision: input type, lane used, reason, cost flag, and timestamp. `/route` must not overwrite the route it is inspecting.
- **Cost Guardrail:** Usage is tracked in a local SQLite ledger by lane: Grok Voice Agent minutes, Ara TTS characters, xAI STT seconds, Gemini 3.1 Flash sight calls, Gemini 3.5 Flash premium calls, Artisan Codex jobs, legacy Kimi coding calls, GPT-5.5 `/complex` calls, Claude review calls, and Grok text/news calls. Telegram `/cost` shows the compact estimate.

Escalate to Gemini 3.5 Flash only when labels are blurry, tiny text matters, hardware risk is involved, confidence is below 60 percent, Zainal says `look carefully` or `double check`, and the system judges that premium sight can plausibly help rather than just needing a clearer frame.

## 6A. Artifact Quality And Skill Model
- **Single Quality Standard:** iMac-quality artifact creation is the standard. Telegram must inherit the same document, spreadsheet, presentation, and HTML quality path instead of using a lighter bot-only workflow.
- **Canonical Document Router:** `DocumentActionRouter` owns normal Markdown, HTML, Word, Excel, and PowerPoint creation. Channel routers may detect requests, but artifact creation should converge on the same builder, QA, memory, and delivery contract.
- **Channel-Specific Delivery Only:** Generation quality should not depend on the surface. The iMac opens or focuses native apps such as Word, Excel, PowerPoint, Cursor, or the browser. Telegram attaches files and sends useful visible text for filenames, paths, and summaries, especially when a voice reply would make a long path hard to understand.
- **Artifact QA Contract:** Every real generated artifact should be describable by one quality result: artifact type, path, pass/fail, summary, issues, warnings, draft model, review model, local validation steps, repair attempt, and delivery readiness.

## 9. Memory Model
- **Local Memory Sources:** iMac interactions, Telegram interactions, and Omi ambient captures all flow into the same memory system.
- **Priority Rule:** Deliberate interactions from the iMac and Telegram have higher priority than ambient memory from Omi.
- **Goal:** Maya should feel continuous across channels, not like separate assistants with separate histories.
- **Memory Ownership:** Gemini should handle summarization, memory distillation, and Omi transcript extraction.
- **Canonical Memory Truth:** Maya should have one canonical truth record per saved fact. Preferences, lessons, curated memory, session search, and compacted summaries may remain as compatibility views or indexes, but they should not each become independent truth stores for the same fact.
- **Canonical Memory ID:** Each saved fact has a stable `memory_id`, `kind`, `subject_key`, `content`, `value`, `scope`, source channel/reference, confidence, status, timestamps, optional expiry, pinned flag, temporary flag, and test marker.
- **Subject Key Normalization:** Direct facts such as `my telegram test drink is teh ais` normalize to a reusable subject key like `telegram_test_drink`. Recall and forget should resolve the subject first, then read or disable that canonical memory.
- **Save Flow:** Explicit learning cues such as `remember that...` write a canonical memory record, then maintain preferences and lessons as derived compatibility records. Maya only says the memory is saved after write and read-back verification.
- **Recall Flow:** Direct memory questions search canonical memory first. If an active canonical answer exists, Maya returns it. If the subject was forgotten, Maya must not resurrect the answer from old preferences, lessons, raw history, session search, or compacted context.
- **Forget Flow:** `/forget` resolves matching canonical memory IDs, marks them forgotten, then removes derived traces from preferences, lessons, curated memory, compacted summaries, raw history, and session search rows. The next recall must say the fact is not saved.
- **Activation Classes:** Memory activation should distinguish pinned memory, active saved facts, recent session context, searchable archive, temporary test memory, and forgotten/expired memory.
- **Prompt Injection Rule:** Pinned memory is always eligible. Active saved facts are injected only when relevant. Recent session context helps follow-ups. Searchable archive is retrieved on demand. Temporary test memories do not become long-term profile facts. Forgotten memory is never injected.
- **Oblivion-Style Decay:** Old memories lose automatic activation strength unless reinforced. Canonical activation scoring combines query overlap, pinned boost, `reinforcement_count`, and age decay. Recall updates `last_used_at` and increments reinforcement so reused facts stay stronger. Pinned memories remain eligible even when there is no query overlap. Temporary test memories expire or stay query-only. Direct user questions may still search non-forgotten archive memory.
- **Manual Pinning Policy:** Pinning is explicit user control through `/memory pin target` and `/memory unpin target`. Maya may suggest pinning a durable rule, but she should not silently pin ordinary preferences, project details, test facts, or casual conversation. Auto-pinning is reserved for approved system-critical operating rules.
- **Canonical Memory Inspector:** `/memory inspect target` is a local Maya audit command. It shows canonical memory IDs, subject keys, activation classes, flags, reinforcement counts, timestamps, and content previews. This inspector is for debugging and governance; it is not injected into normal replies unless Zainal explicitly asks for it.
- **No Guessing On Direct Memory:** If canonical memory has no active answer for a direct memory question, Maya should say she does not have it saved. She should not guess from garbled transcripts or stale chat context.
- **Session Context Window:** Maya has a shared context-window layer that behaves like Codex-style compaction. Older shared iMac and Telegram history is compacted into `session_summaries`, then injected back into the answer path as continuity support. This is channel-neutral, so switching between Telegram and iMac should still feel like one ongoing Maya.
- **Hermes Style Curated Memory:** Maya keeps two bounded curated memory stores inspired by Hermes Agent. `maya_core_memory` is capped at 2477 characters for Maya environment facts, Kampung AI operating rules, and durable tool lessons. `zainal_profile_summary` is capped at 1499 characters for Zainal's preferences, communication style, work habits, and personal assistant context. These are injected into Telegram and iMac voice prompts, while raw history stays searchable instead of being stuffed into every prompt.
- **Session Search:** Maya indexes normal Telegram and iMac voice history into SQLite FTS5 so she can search old conversations on demand. Session search is for recall; curated memory is for critical facts that should always shape behavior.
- **Memory Soak Expectation:** Long no-key conversations should compact without losing durable preferences, hard facts, or shared continuity context. The rehearsal keeps a long-session soak test so context-window regressions are visible before provider day.
- **Token-Aware Compaction:** The compactor uses an internal estimated token budget instead of a small fixed message count. Zainal does not need to see token math during normal use; Maya should simply keep the thread alive longer and compact when the prompt budget is getting crowded.
- **Topic Threads:** Session summaries are saved both as shared continuity and as topic-scoped context so Maya can keep separate threads from blurring into each other.
- **Fact, Vibe, Summary Separation:** Durable hard facts and rules are preserved in `context_facts`, fuzzy tone or theme signals are preserved in `context_vibes`, and lossy conversation summaries stay in `session_summaries`.
- **Context Inspection:** Telegram `/context` and natural questions like `show context window` expose the latest compacted shared context without calling any provider.
- **Memory Control:** Zainal can inspect memory sources with `/memory`, remove specific memories with `/forget`, link legacy preferences and lessons to canonical memory IDs with `/memory migrate`, and clean stale compacted context with `/memorycleanup`. The migration command reports scanned rows, source links, canonical creates/updates, duplicate links, and skipped internal rows. Confirmed preferences and lessons should not be wiped by stale cleanup.
- **Project And Task Retention:** Project and inactive task records expire after 90 days without activity, enter a 7-day deletion warning, then hard-delete Maya records only. Local project folders and user files are never deleted by retention. Talking about, opening, editing, or writing memory for a project/task renews it for another 90 days. Passive search, listing, cleanup scans, and weekly distillation do not renew it. Deleted project/task records must not be reintroduced by weekly memory or archive search.
- **Memory Source and Confidence:** Memory inspection should show source and confidence where available: preferences are high confidence, lessons carry their logged confidence, and compacted context summaries are medium confidence continuity support.
- **Weekly Memory Distillation:** The useful production version of the "quantum memory" idea is a weekly distillation pass. Once a week, Maya should gather iMac, Telegram, and Omi logs, let Gemini 3.1 Flash remove noise and summarize the week, optionally use Gemini 3.5 Flash for premium synthesis if the week is dense or ambiguous, use GPT-5.5 only for high-value memory shaping when needed, then save clean durable facts through canonical memory, with preferences, lessons, tasks, and weekly summaries as views or downstream stores. The provider path records Gemini Flash usage for normal weekly distillation and Gemini Premium usage only when the run is dense, ambiguous, or explicitly forced. Claude reviews candidates for overreach, false assumptions, vague preferences, unsafe memory, and confirmation-needed facts before canonical writes. Live provider distillation must write new stable facts only through `upsert_canonical_memory`; it must not create a separate truth store in preferences, lessons, curated memory, or raw summaries. The iMac host should run this automatically every Sunday at 20:00 through the `com.kampungai.maya.weeklymemory` launchd job.
- **Weekly Canonical Input:** Weekly memory should read active non-temporary canonical memories, selected high-value summaries, and current open loops. It should exclude temporary test memories by default, never recreate forgotten facts, merge duplicates by subject key, and record which canonical memories shaped the summary when live distillation is enabled. Each saved weekly summary stores `canonical_memory_ids` as structured JSON and includes a concise ID line in the summary text for auditability.

- **Memory Application:** Maya should not just store memory; she should retrieve relevant preferences, active tasks, and durable knowledge before answering.

## 13. Engineering Discipline
- **Shared Rule for Artisan Implementation:** All code contributors must keep code readable for both humans and AI agents.
- **300-Line Code Limit:** No `.py` file should exceed 300 lines. Files in the 280 to 300 range are allowed but treated as urgent refactor candidates.
- **One Clear Responsibility:** Each file should own one clear part of the system.
- **No Splitting for Show:** Do not split code just to satisfy the line count. Split only when there is a real module boundary or readability gain.
- **Facade Pattern:** When a large module has existing callers, keep a small public facade if needed and move focused behavior into helper modules. Facades preserve imports; helper modules own real logic.
- **Early Refactor Signal:** When a file reaches 250 to 280 lines, treat it as a warning sign and look for a clean extraction before it becomes hard to reason about.
- **Prompt Enforcement:** Artisan implementation prompts must include these rules directly, not rely on project docs alone.
- **Tooling Enforcement:** `code_health.py` and `doctor.py` should report file-size health so line drift is visible before it becomes a problem.
- **Why This Matters:** Smaller focused files reduce token load, make AI reviews faster, lower confusion, and prevent another giant-file problem.
- **Routing Boundary:** `assistant.py` should stay as the composition layer. Channel routing decisions belong in `assistant_routes.py` so the main assistant file does not become another giant switchboard.
